## 一つの構造と計算計画

本文と役割付き参照、出典、版が正本です。親も普通のAtomで、意味上のまとまりに対して必ず数値キャッシュを作る仕様にはしません。試作の範囲指定は計算のヒントです。任意のroleを「所属」と解釈する規則は追加していません。

入れ子でない範囲が共有するAtomは境界に残します。同じAtomを別の内部変数として複製しません。子の消去後に親が残りの境界を消去することもできます。外部との接続が密で不利なら消去を省略します。この判定は係数数のヒューリスティックで、速度向上の保証ではありません。

計算を畳む都合で、親の要約、意味関係、本文ベクトルを追加・変更しません。Writer、入力取得、モデル実行、履歴採用、ジョブ、費用管理は外側の責務です。

## 数値計算の契約

`T` は出辺の重みを正規化した列方向の遷移行列です。出辺のない列はゼロです。正規化seedを `s`、伝播率を `a` として、次を解きます。

```text
A = I - a*T
y = solve(A, s)
r = y / sum(y)
```

この `r` は、現行の「行き止まりの値をsへ戻す」Personalized PageRankの収束解です。行き止まりからの戻り先を係数へ埋め込まず、係数を文脈から独立させます。

内部 `I` と残す境界 `B` の消去は、次の式です。

```text
H   = solve(A_II, A_IB)
S   = A_BB - A_BI*H
z   = solve(A_II, s_I)
y_B = solve(S, s_B - A_BI*z)
y_I = z - H*y_B
```

内部seedも正規化に必要な内部massも保持します。大きな逆行列を明示的に作らず、ピボット選択付きLU分解を使います。ただし初期行列と境界は密行列です。最大1,024変数の小規模試作用で、大規模な疎行列ソルバーではありません。

現行の既定検索は最大32反復またはL1差分1e-6で停止します。収束解との一致を、その中間値とのビット単位の一致とは呼びません。同じ計算計画でも、丸め誤差に近い同点の順序まで全解法で一致する保証はありません。

## 差分補正と再利用

文脈変更と関係変更は同じ線形評価器へ渡します。

```text
d = s_new - A_new*y_old
delta = solve(A_new, d)
y_new = y_old + delta
```

補正するのは正規化前の `y` です。正規化済みの `r` をそのまま代用しません。残差は負にもなるため、内部復元と上界計算は符号を扱います。過去の関連度へ意味上の加点を行いません。

呼び出し側は、前の `y` の各位置を現在の同じAtom IDへ対応付ける必要があります。試験ではIDが一致する場合だけ再利用します。ID集合が変わったらcold評価へ戻し、位置だけで対応を推測しません。

係数キャッシュのキーは内部と両方向の境界行列を含みます。出辺の追加で正規化の分母が変わると、関連する係数も無効になります。キャッシュは係数個数に上限を持つプロセス内LRUです。本文、認可、検索結果、現在性の証拠は保存しません。

既存の取得・認可・鮮度確認経路を毎回実行してから、数値計算へ渡します。キャッシュの有無から読めるAtomを決めません。残差作成にも現グラフの辺の走査が必要で、局所変更が常に安いとは限りません。

## 上界を使う詳細化

閉じた範囲について、内部入力 `z` の範囲と `H` の列ごとの係数範囲、境界の値から、まだ復元していない値の区間を作ります。浮動小数点の丸め方向を外側へ広げます。依存先の境界を先に評価できる消去順を使い、共有点の復元費用は一度だけ数えます。

既知のk位の値が全未復元候補の上界を上回れば終了します。上界が競合する範囲を、上界と必要な復元個数に基づくヒューリスティックで選びます。予算内で確定できなければ `certified: false` を返し、同じ数値queryで再開できます。同点は保守的に扱います。

この試作の `certificateScope` は **`compiled-numeric-scores`** です。これは、同じ分解済み係数・右辺・正規化値で全変数を浮動小数点復元した場合の上位候補に限ります。LU解法の誤差を含む数学的な厳密PPR、グラフ外の候補、全記憶の検索完全性への証明ではありません。

予算は、境界以外で復元した変数の累積個数です。内部右辺のsolve、境界solve、上界評価、行列作成、グラフ取得は別途必要です。`required` は指定された数値変数を確実に開くための試験用指定で、製品の必須条件・出典の閉包を代替しません。従来の全スコア比較に加え、現在は `reader.mjs` が未復元の候補を上界で評価し、必要な根拠のスコアだけを復元して共通の逐次パッキングへ渡します。

## 実行方法と結果

リポジトリのルートで実行します。数値比較は固定エンコーダー、意味検索の比較は保存済みの実モデルの埋め込みを使います。LLMや有料APIは呼びません。


測定結果には基準コミットと実行ソースのSHA-256を記録します。`--record` だけが `results.json` を更新します。

数値試験は90個の固定乱数グラフ×3消去計画と、120ケース×4回の文脈・関係変更を含みます。行き止まり、循環、内部seed、ゼロ入力、共有・入れ子・重複所属、密な境界、キャッシュ退避、符号付き補正、上界、同点、予算、中断・再開を比較しています。

Memory/SQLiteの試験では、本物のAtomを保存し、既存の候補取得・認可・鮮度・展開経路を使います。既存の `finishRanking` と比較するため、基準コミットの数値入力構築だけを研究ハーネスへ写しています。ライブラリ側の関数は変更していません。本文・返却順・必須条件・policy分離・失効・purgeを比較します。

157 Atomの測定では133変数を12範囲へ畳み、24変数が境界に残りました。収束反復との差は最大約1.1e-14です。文脈変更では13係数を再利用して新規計算0、一部の所属変更では11係数を再利用して2係数を再計算しました。

このfixtureの上位5候補は境界にあります。12文脈とも内部の個別復元を省いて確定できましたが、内部の右辺計算は実行しています。上位候補が内部の例外条件にある一般的な会話履歴の品質を証明する結果ではありません。内部への直接一致や予算再開は、別の小さな固定例で検証しています。

数値評価は数百分の1ms程度ですが、キャッシュ付き再計画は約0.7ms、グラフ取得はMemoryで約140ms、SQLiteで約1,800msです。正確な実測値は `results.json` を参照してください。測定は環境や時刻で変動し、取得削減は0回です。上界やwarm補正の費用も測定に含めると、常に全復元より速くなるわけではありません。

## 出力費用を含む比較

`reader.mjs` は、現在の上位候補を変え得る未復元値を評価し、復元費用と既知の必須条件・出典の量から開く場所を選びます。この費用は選択用の推定です。採用時にはライブラリの `createPacking` が引用の共有も含めた正確なトークン数を計算し、条件の一部分だけを返しません。高順位の候補が収まらない場合は、その候補を保留して次を評価します。返却順位の契約は既存パッキングと共有します。

数値作業量の上限は係数適用、区間の端点計算、候補・条件の走査を数えます。FLOPsや同一CPU費用ではないため、実時間も併記します。グラフ取得・前処理・出力のストレージ使用量は別途記録します。未確定で終了した場合は、未評価候補数と残る上界を返します。更新・認可変更・purge後に古い計算状態のまま再開せず、再取得を要求します。

[reader-results.json](reader-results.json) はMemory/SQLite、共有構造/重い必須条件、4評価方式、3段階の共通予算を比較しています。出力は基準パッキングの順序付き接頭部分と一致し、確定時は本文・出典も一致しました。条件欠落は0件です。合成評価は常に最速ではなく、全体分解やフラット評価が速い条件もあります。取得省略は0回です。

数値だけの規模比較も128 / 1,024 / 8,192変数で行いました。1,024変数では合成計算の再利用に利点がある一方、初回準備はlocal-pushより高くなりました。密行列を使う試作は1,024変数が上限です。8,192変数では疎なlocal-pushが同じ作業量予算で収束し、フラット評価は途中終了しました。これは本文取得を含む大規模運用の評価ではありません。

local-pushは疎な遷移と優先度ヒープを使い、残差を局所的に前へ送る比較実装です。残差を外向き丸めで再評価し、固定された浮動小数点遷移行列について正規化後の区間を求めます。BEARDそのものの実装・性能再現とは呼びません。[基礎となる先行](https://www.kdd.org/kdd2016/papers/files/rfp1146-zhangA.pdf)

## 実埋め込みで見つかった弱点

[semantic-results.json](semantic-results.json) は、日本語の合成コミュニティ資料97 Atom（活動記録72件を含む）と6問を、多言語MiniLMの実埋め込みで比較した記録です。構造は資料の固定規則から作り、質問を入力して構造を修正していません。ただし独立した第三者による盲検評価ではなく、AI Writerの構造化品質を試験したものでもありません。

8,192バイトのコンテキスト・最大8項目の条件では、全候補または64件をseedとした場合、説明Atomが順位と出力枠を占め、必要な原資料の範囲を取得できたのは0/6問でした。8件へ絞ると6/6問で主張と条件を取得しました。すべての評価器で同じ傾向です。これは実行方法の変更だけでは直らない、入口選択・正規化・出力選択の問題です。8件を一般的な最適値として採用する証拠にはしません。

根拠の取得はAtom IDの一致だけでなく、元資料の主張・条件のバイト範囲が返却されたかで測ります。元資料全体が返れば、その中の範囲も取得済みと扱います。seedの取り逃し、グラフの切り詰めと再正規化、数値誤差を別々に記録し、全記憶に対する完全性は宣言しません。top-8制限は感度試験でありANN実装の評価ではありません。

モデルは [Xenova/paraphrase-multilingual-MiniLM-L12-v2](https://huggingface.co/Xenova/paraphrase-multilingual-MiniLM-L12-v2)、revision `2c4055b12046f11709e9df2c122e59ffbdc2f900`。Transformers.js 3.8.1、q8、mean pooling、正規化、ローカルCPUを使いました。実行済みベクトルは `semantic-vectors.json.gz` に保存し、比較の再実行にモデルのダウンロードは不要です。

再生成する場合だけ、別ディレクトリへ `@huggingface/transformers@3.8.1` をインストールし、`ATOM_TRANSFORMERS_MODULE` にその `src/transformers.js` の絶対パスを指定して `node research/composition/embed-semantic.mjs` を実行します。重みは研究用キャッシュへ保存し、npmパッケージに入りません。

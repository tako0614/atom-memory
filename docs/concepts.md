# Atom と関係

情報、まとまりの説明、関係自体を一つのAtomモデルで表します。親と子は関係上の役割です。巨大な親のメンバー配列を書き換える必要はありません。`資料/補足`、`対象/理由`など、任意の役割で同じ保存と探索が動きます。

```text
まとまりの説明 ← 資料: 関係Atom :補足 → 一つの情報
                       :理由 ↓
                         根拠
```

役割と順序は意味を持ちます。三者関係を全対の二項関係へ分解せず、同じ対象の繰り返しや別の役割も残します。分類ラベルを知らずに探せることと、役割の自然言語上の意味を完全に理解できることは別です。

## 固定版と現在の関係

refは同じ論理対象と観測した版を解決します。inspectの既定は観測版、改訂はその版を前提にCASを行います。通常のlinksは論理対象へ接続し、読取snapshotで対象版を選びます。固定版リンクは明示設定で選びます。

旧Kernelの`include`は固定構成で、有限バッチ内の循環を拒否します。通常の意味的リンクには循環を許し、訪問済み版・深さ・候補予算で停止します。世界全体をDAGに変えません。

## 後継と歴史のまとまり

`draft.supersede(oldRef, newRef)`だけが現在の整理の後継を採用します。同じ役割名の関係や「置き換える」という本文だけでは選択を変更しません。別視点の新しい親は、明示的にsupersedeしなければ並存します。

採用時には旧親の版だけでなく、その読取状態で接続していた関係と子の具体的な版を不変manifestへ記録します。初版はローカルsnapshot上の接続成分を有限に記録する方式で、既定256 Atomまでです。取り切れなければ`HISTORY_INCOMPLETE`で編集全体を不成立にします。大きい整理のための保持可能なリモートsnapshotは未実装です。

`inspect(oldRef, { history: 'retained' })`で旧構成をページ取得できます。既定の保持期間は30日。期限付きreceipt/cursorが切れても、manifestと不変版から読みます。この版のローカル保存は旧版を自動GCせず、少なくとも保持期間内に必要な版が存在する前提です。期間後の履歴取得は`HISTORY_EXPIRED`です。削除と権限失効は期間内でも優先します。

後継の競合と循環を拒否します。初版は一対一のみで、分割・統合の多対多採用はありません。同一callbackで同じ論理Atomを複数回改訂する操作も未対応です。

## 出典・失効・再生成

原資料には不変版とUTF-8の範囲・digestがあります。生成物の引用だけでなく、モデルが入力として見たAtomと範囲観測をホストが記録します。通常の読取履歴と現在性の前提は別に管理し、意図的な過去版分析を最新版でないという理由だけでは拒否しません。

子の改訂、関係範囲への新規挿入、入力した上位生成物や設定の変更を検証します。古い派生物は現在の表現として返さず、許可された原資料へ戻り`pending`を表示します。明示的な`generator`をホストが設定すると、共有予算内で一時表現を再生成できます。一時cacheは意味Atomへ自動公開しません。すべての祖先を同期生成してからwriteを完了する方式でもありません。

元資料の出典と文章の意味忠実性は別です。sourceは入力主体の発言記録、生成仮説や要約は生成由来として区別し、同じ信頼度へ平坦化しません。

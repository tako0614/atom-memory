# v0.8 設計判断

基準は `a2f3c59098ba7f6a46ffd3903d2fc14fa43335f5`、v0.7.0。意味の正本は[規範仕様](/specification)、実行記録は `validation/v0.8.0.md` です。

| v0.7で結合していた責務 | v0.8の扱い                                                                    |
| ---------------------- | ----------------------------------------------------------------------------- |
| 検索順位と返却集合     | 同じ活性を維持し、required閉包・共有表示の実費用で集合を選択                  |
| 通常関連と消去依存     | ホスト観測済み生成/信頼済み原資料は区別。旧版・tokenなしagentは旧依存を保持   |
| commitと生成単位       | 一つのcommitへ複数InputTokenを保存可能。共通tokenの入力は引用で分割しない     |
| 取得と本文提示         | acquisition/presentation/generation/watch/ackを同じversioned manifest内で区別 |

InputTokenは信頼したホストの入力確定記録です。全payloadと持越し状態の申告が不正なホスト、モデル内部の不可観測な状態まで追跡する保証はありません。検索候補を表示したことにはしませんが、使用した選択入力は監査・消去依存へ残します。

新しいsource契約では独立本文に認可済み通常関連を作れます。関連先が後から読めなくなっても本文を残し、安全なunavailable形で返します。出典と生成内容のpolicy越境は許しません。legacyの全linksは引き続き消去依存です。

消去は再開できる有限管理操作です。未完了時は安全のため保存先全体の公開read/writeを一時停止します。ジョブの自動再開、バックアップの回収、外部モデルからの情報回収はCoreへ追加しません。

選択の比較には同じ条件閉包・表示版・tokenizerを使います。v0.7順位順policyの原本は `research/v08/retrieval-v07.ts.txt` に凍結しました。Uは代理目的で、意味品質や新規性は別途測定が必要です。新しい実LLM評価は今回の決定的な構造試験に含めません。

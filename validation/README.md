## 同じ資料・モデル・総予算での比較

合成資料と同じ決定的モデルを使い、4ステップで話題を変更し、途中に原資料の訂正を投入しました。sourceの訂正は各条件に同じ外部入力イベントとして適用しています。ハーネスのモデル呼出しと取得は同じ総予算です。古い履歴追記は比較用wrapperだけで再現しています。

| 条件               | 必要根拠が入力に入ったステップ | input tokens | 訂正後に旧情報が残ったステップ |
| ------------------ | ------------------------------ | ------------ | ------------------------------ |
| 自動readなし       | 0 / 4                          | 3,716        | 0                              |

| 自動read＋記憶置換 | 4 / 4                          | 4,825        | 0                              |

このtoken数は参照用UTF-8 byte語彙によるものです。実サービスの課金token数ではありません。原資料の条件本文は取得した入力に残りました。回答の意味的正しさ・条件の自然言語上の理解は、このmock比較では評価していません。実モデル用の比較コマンドは`npm run evaluate:live`で、モデル応答も別途保存します。

語彙の正解をID順の最後に置き、無関係Atomを10 / 100 / 1,000 / 10,000件追加したローカル全走査では、いずれも正解が1位でした。完全走査のmaxScanは20,000、候補予算は30,000に揃えました。10,001件の走査は159.10ms、課金した候補操作は10,003、本文bytesは290,311でした（この1回のローカル測定）。隣接関係10 / 100 / 300件は全件まで再開し、同じ版を前提にした2 / 8 / 32件の改訂は各条件で1件だけ確定しました。これらは合成fixtureでの整合性・局所費用の測定です。一般の意味検索品質、ANN精度、分散スループットの証拠ではありません。

## 未実行・未実装・制約

- 実LLMは上記の一つの合成fixtureを実行しました。Writerサンプルはホストが記述→関係→終了の現在段階を明示する有限ワークフローです。一般の自律計画・終了判断の成功を意味しません。1.5Bモデルの参照誤生成・反復と、7Bモデルの終了反復も`live-attempts.json`に保存しています。どの失敗実行もprivate overlayを部分公開しませんでした。
- 候補取得はローカル完全走査の比較方式です。独立した大規模FTS/ANN、分散保存・分散索引・分断耐性、実データでの品質評価は未実装・未検証です。処理した候補数/bytesはDB内部I/O全体の厳密な上限ではありません。
- モデル内部の隠れ状態の写像、生成途中へのコンテキスト挿入は未実装です。互換性不明のベクトルを拒否します。
- 必須条件は`required: true`または旧固定includeとしてホストが表現します。必要な条件を自然文だけから完全に発見する機能ではありません。
- 一つのeditでは一つの論理Atomにつき一つの改訂案です。後継採用は一対一のみで、分割・統合の多対多は提供しません。
- 旧構成はローカルsnapshotの接続成分を既定256 Atomまで不変manifestへ保存し、既定30日保持します。予算内で取り切れなければ編集全体を失敗させます。receipt期限に依存しませんが、ホストは不変版の物理保持・容量・バックアップを管理する必要があります。削除と現在の閲覧許可を常に優先します。
- 決定的試験の成功を、モデルの意味品質、タスク成功率、研究上の新規性の達成とは報告しません。
